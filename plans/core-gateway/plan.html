Decisions already made in the plan

What is hard to undo

  1. Core is not edited. Every gap is filled in our gateway.Core is the teammate’s code. When they add “release a hold” or “close a sale”, one gateway method switches from refusing to calling core.
  2. A draft lives only in our gatewayCore has no drafts, and cannot remove a tier. So the event is created in core only on Publish. Before that, Chai can change anything.
  3. “Not built yet” is a 409 with code NOT_IN_CORE, never a 5xxOur router treats any 5xx as “you are offline”. A 409 shows the message on the page instead.
  4. Core runs on the demo clockThe demo panel’s speed and +10 min still work on core. Scenario buttons (race lost, bank slow, and so on) are refused, because core has nothing to fake.
  5. 200 per second undoes a recorded decisiondocs/08 lists “200 → 12” as change 8, with the reason. The plan rewrites that row to say the team went back to 200 on 11 Oct, and the SCR-38 helper still shows the careful number, 7,500 ÷ 600 ≈ 12.
